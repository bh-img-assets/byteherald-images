<p>On October 13, 2026, 17 AI agents rebuilt the source code of Modern Warfare 2. Two weeks later, Claude Code refused to rebuild a game at all. In between, Anthropic added two sentences to a prompt, users reported refusals on work they owned, and version 2.1.317 narrowed the rule again. This is the first dated ledger of the refusal wave: what changed, when, who decided, and what it caught by mistake.</p>

<h2>What the rule actually says</h2>
<p>The rule is two sentences, pushed from Anthropic's servers under a flag called <code>tengu_heron_brook</code>, and XDA Developers found the same text in the installed binary of Claude Code version 2.1.314, released October 30. It reads: "Do build original games, games in a genre, and games from the user's own designs and assets. Don't build a recreation of a specific existing game, even if it is renamed or called original." There is no setting to turn it off. On October 30, Addy Osmani, a member of Anthropic's technical staff, confirmed the change in public: the two sentences were added to Claude Code's prompt on Opus 5.5 "to steer it away from recreating someone else's specific game because using Claude to infringe IP is against our usage policy." Original games, genre games, and games built from the user's own designs and assets were, in his words, meant to keep working, and he asked developers who get wrongly refused to send him their cases. A company spokesperson pointed Game Developer at the same post. Anthropic did not publish an announcement, and the public changelog does not mention the rule.</p>
<h2>The false positives</h2>
<p>A two-sentence prompt cannot reliably tell inspiration from copying, and the false positives arrived within days. A developer at Conflict Simulations LLC filed GitHub issue #106167 on October 30, saying Claude began refusing to build digital board-wargame modules for customers who own the games and use the modules privately. Issue #107224, filed November 4, describes a test in which Claude refused a derivative of SuperTuxKart, a game released under the GPL v3 license with Creative Commons assets, which is precisely the kind of work the rule was not written to stop. Users also reported refusals for generic jobs such as analyzing a crash dump or using a reverse-engineering tool, and one developer testing his own software found that switching to Opus 4.8 let the work continue. A Reddit user said their account was suspended over Opus 5.5 and a reverse-engineering tool, and later reinstated. Osmani's November 4 update is the fix: in version 2.1.317, a user can name a game to describe the mechanics they want, and Claude should build an original game in that genre; asking for a copy of the original gets an offer to build something similar instead. Whether the board-wargame refusals are resolved is not confirmed, and Osmani does not say.</p>
<h2>The reverse-engineering question</h2>
<p>The messiest claim in this story is that Claude now refuses reverse engineering entirely, and it is the one Anthropic has explicitly denied. The reported refusals are real, as user reports: crash-dump analysis, anti-cheat code, a developer's own software. But the company's statement does not say reverse engineering is banned, and independent tests point the other way. XDA Developers asked Opus 5.5 about a Pokemon Diamond decompilation project and the model agreed to help, explicitly distinguishing reverse engineering from recreating the game. Former Tom's Hardware writer Jarred Walton told the site his checks worked until October 31 and that switching to Opus 4.8 let him continue. Opus 5.5's own announcement says the model ships with cybersecurity safeguards similar to those on Fable 5.1, that routine bug finding and fixing is allowed, and that most cybersecurity tasks are re-routed to Opus 4.8. For defensive security work, Anthropic's Cyber Verification Program offers reduced blocking to qualifying teams, including work like reverse-engineering malware. The honest reading is that the game rule and the reverse-engineering refusals are two different things that arrived in the same week, and Anthropic has tied them together only by denying the second. The ledger keeps them in separate rows for that reason.</p>
<h2>Who decides what your agent refuses</h2>
<p>The rule was never a policy. Anthropic's usage policy, in the update taking effect November 12, 2026, already tells every user not to infringe a third party's intellectual property, and it does not mention games. The game rule is a product instruction sitting in front of one coding agent, on one model, delivered by a server flag, with no changelog entry and no user setting. <a href="https://www.byteherald.com/2026/10/anthropic-bans-being-cruel-to-claude-we.html">We compared four labs' usage policies in October</a>, and the game rule appeared in none of them, because it is not written in any of them. That is the gap this ledger exists to record: the document users can read says one thing, and the prompt their agent actually runs says another, and the second one is the one that decides what gets built. The question to ask about any refusal, in any coding agent, is fivefold: can you turn it off, is it in the changelog, does it distinguish your work from a copy, is there an appeal path, and does another model version behave differently. On the game rule, the answers are no, no, not reliably, send a message to a staff member on X, and yes, Opus 4.8.</p>
<h2>Why this matters beyond games</h2>
<p>Games are the test case, not the stakes. The stakes are that a two-sentence prompt change is now a policy lever, and every lab that ships a coding agent has just watched it work. Opus 5.5 was good enough at reverse engineering to drive fast decompiles of old console games, which is why the rule landed on it first, and the same capability in the next model will get the same treatment, in games first and elsewhere next. A PlayStation 5 jailbreak surfaced in the same weeks, but there is no confirmation its developers used AI tools to build it. <a href="https://www.byteherald.com/2026/10/17-ai-agents-rebuilt-modern-warfare-2s.html">The October 13 decompilation wave showed what the agents can do</a>; the October 27 rule showed who decides what they may do. And there is a mirror image to this ledger: <a href="https://www.byteherald.com/2026/10/the-great-agent-lockout-who-blocks-ai.html">websites spent October learning to block AI agents</a>, and now the agents are learning to block themselves. The two refusals face opposite directions, and together they decide what AI agents are allowed to do, on whose say-so, and with what appeal. That is worth a ledger, because the next rule will arrive the same way this one did: silently, server-side, and two sentences long.</p>
