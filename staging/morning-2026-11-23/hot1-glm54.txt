<p><a href="https://z.ai/blog/glm-5.4">Z.ai released GLM-5.4 on November 23, 2026</a>, calling it the first flagship model built on a Loop Transformer and saying it reaches intelligence comparable to models with 2 to 3 trillion parameters, at 750 billion parameters. The claim is the headline. The evidence is narrower: the launch post publishes no benchmark scores for the 750B flagship at all, and its only scored table comes from a 30B ablation. In plain terms, GLM-5.4 is a 750B-parameter coding model that runs 28 of its layers twice per token instead of adding parameters, and Z.ai says that loop puts it at the level of 2T to 3T models, a claim its own launch post does not score directly.</p>

<h2>What the loop actually does</h2>
<p>In a standard Transformer, each layer runs once per forward pass. In a Loop Transformer, a group of weight-shared layers runs for multiple iterations, refining the hidden states from the previous pass, which gives a deeper network without increasing the parameter count. GLM-5.4 loops 28 layers of the GLM-5 base model for two iterations. The idea is not new: the 2018 Universal Transformer proposed weight-shared depth, but looped models trained from scratch still lagged unshared models under the same pretraining compute budget, so Z.ai instead adapted an already pretrained base model into a Loop Transformer through continued training, raising what the company calls the intelligence ceiling with a relatively small compute overhead. The architecture was validated progressively across 1B, 4B, 30B, and 750B base models.</p>
<p>Three engineering changes make the loop work at 750B scale. Gated Progressive Updates use independent per-token gates for each iteration, writing candidate updates back into the residual stream proportionally so activation norms do not blow up; the first pass writes conservatively, the second opens the gates for full updates. A Hybrid KV Cache lets the second loop reuse the sparse key-value pairs selected in the first pass while keeping its own new pairs in a sliding window, so an extra loop costs one sliding window of cache rather than a full context cache. Sparse Attention Index Reuse lets the second loop reuse the attention indices from the first loop, adding zero indexing overhead, and Z.ai says experiments show it performs nearly identically to recomputing indices on every pass. Throughput is stated as up to 200 tokens per second off-peak and 70 to 80 tokens per second at peak load.</p>
<h2>The only scored table is a 30B test</h2>
<p>The launch post's single scored table is a controlled ablation on a 30B model with the same architecture as the 750B base, at identical parameter counts and only about 10 percent more total training compute, evaluated after 200K long-context supervised fine-tuning with thinking mode enabled. The looped version gains everywhere, and its output gets shorter almost everywhere, which Z.ai reads as reasoning moving into the implicit depth of the loop.</p>

<p>The honest reading is narrower than the headline. The ablation shows the loop helps at 30B, with the largest gains in math, scientific reasoning, and long-context tasks, and average output length down 10 to 14 percent on most benchmarks. It does not show what the 750B flagship scores on any benchmark, and the post names no rival model and publishes no head-to-head table against GPT, Claude, or anyone else. The 2T to 3T comparison is Z.ai's characterization until a directly comparable evaluation exists. Benchmarks are only useful when the comparison is like-for-like, which is why <a href="https://www.byteherald.com/2026/11/how-intelligence-index-v5-rewrote-ai.html">we track how the leaderboard itself is built, and what changed when the Artificial Analysis index moved to version 5</a>.</p>
<h2>What an independent test found</h2>
<p>The first independent test, from AI blogger AICodeKing on his KingBench 4 programming leaderboard, scored GLM-5.4 at 55.3 percent, seventh of 19 models, and the relay describes it as the top-performing open model on that list. The interesting numbers are the costs: GLM-5.4 took 431 minutes to complete the full test while Gemini 4 Neon finished in 109 minutes, executing 1,128 steps against Neon's 246, and consuming 1.04 million tokens against about 70 thousand for Neon, nearly 15 times as many. Its per-step speed was actually faster, 22.9 seconds against Neon's 26.7, but it took far more steps. AICodeKing's verdict, as relayed, was that GLM-5.4 is the most cautious model he has ever used, and he recommends it as a code reviewer or for complex engineering planning rather than letting it handle every task. One blogger's six-project test is not a benchmark, and it is the only independent measurement available so far, but it captures the cost of a limitation Z.ai admits in the launch post: GLM-5.4 tends to get caught in overly long marathon thinking loops. Z.ai says that prolonged reflection and self-correction does consistently improve accuracy beyond its parameter count, and the independent test shows what that improvement costs in time and tokens.</p>
<p>The looped design also puts GLM-5.4 in the same weight-shared recurrent family as GPT-6 Astra, according to the Lookonchain summary of the launch, which is a reminder that the architecture race is now about depth per parameter, not just parameter count. On price, Z.ai's published credit multipliers for GLM-5.4 are 4.6 for input, 1.1 for cached input, and 16 for output, against 6.9, 1.7, and 24 for GLM-5.3, so the same work costs fewer credits, though no dollar prices have been published. <a href="https://www.byteherald.com/2026/10/flash-models-priced-cheapest-pick.html">Flash-tier pricing changes by the hour, and our priced comparison of four flash models shows how fast the cheapest pick flips</a>.</p>
<h2>What you can actually use today</h2>
<p>GLM-5.4 is available to GLM Coding Plan subscribers, selectable as glm-5.4[1m] in Claude Code and as glm-5.4 in ZCode, Trae, and other supported tools, plus Z.ai Chat. The standard pay-as-you-go API is listed as coming soon, with prices unpublished, and the model weights are planned for open release only after safety hardening, with no date or license given. Unlike text-only GLM-5.3, GLM-5.4 natively accepts images, so it can inspect UI mockups, diagrams, and rendered visual bugs directly, and Z.ai's demos show it writing code for a self-narrated video, a 6-axis robotic arm in engineering-grade CAD, a complete game, and an interactive 3D bird-watching scene built from pure mathematical geometry. That is the Generalized Coding pitch: code as the foundation for video, engineering, games, and 3D, not just software. The test that matters has not been published yet: a same-task engineering win rate for GLM-5.4 against GLM-5.3. Until independent benchmarks on the flagship, API pricing, and the weights release arrive, the loop is proven at 30B and promised at 750B.</p>
