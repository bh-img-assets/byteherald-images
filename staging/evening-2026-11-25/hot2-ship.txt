<p><a href="https://techcrunch.com/2026/11/23/anthropic-launches-claude-ship-letting-ai-agents-review-fix-and-approve-code-changes/">Anthropic launched Claude Ship on November 23, 2026, a suite of AI agents that takes a pull request from review through fixes to an approval decision</a>. The review part is familiar. The approval part is not: for the first time, an Anthropic agent can sign off on a code change by itself, under rules the team writes as a file in the repository. The launch is in beta, for Claude Team and Enterprise customers using GitHub repositories, and Anthropic's own advice is to start in observe-only mode.</p>

<h2>Three pieces, one pipeline</h2>
<p>Claude Ship is not a single agent. It is three components working a pull request in sequence, and the split between them is the design. Code Review is already generally available. It checks a pull request against the codebase, verifies and categorizes its findings, and posts the results to the pull request. Review depth is configurable at the repository level, with teams choosing between Quick, Standard, and Deep reviews. PR Steward is new and in beta. It works through failing continuous integration checks, merge conflicts, and review feedback, whether that feedback comes from Code Review, another tool, or a teammate, and it comments after every push on what it changed and how to roll it back. PR Steward cannot approve or merge anything. Claude Approvals is also new and in beta, and it is the bigger shift. It applies an approval policy the team writes as a file in the repository, and if the policy allows it, Claude can approve routine changes on its own.</p>
<p>The bottleneck Ship targets is the step after code generation. <a href="https://www.byteherald.com/2026/10/5-ai-coding-assistants-one-scorecard.html">Our October 11 pillar tested five AI coding assistants on the same ten tasks and measured how fast they write code</a>. Ship addresses what happens next, when AI-generated code arrives faster than human engineers can inspect it. Anthropic says that is already the case on its own Claude Code team, where Claude writes most of the code, and the team wanted everything after the pull request to move just as fast. For individual developers, a new /ship command in Claude Code and the desktop app pushes a change, opens the pull request, runs the review, and works through feedback and failing checks. For admins, Ship can be turned on for an entire repository and then works across its pull requests automatically.</p>

<h2>The approval is a policy file, not a setting</h2>
<p>The consequential design choice is where the approval rules live. A team writes its approval policy as a file in the repository, which Anthropic describes as a smarter CODEOWNERS file. The policy can let routine changes through automatically and route riskier ones to a human, and the decision can weigh a variety of signals, including Code Review findings or the team's own classifiers written in natural language. Because the policy is a file, it can be versioned, reviewed, and audited like any other part of the codebase, instead of sitting as a setting buried in a dashboard. The approval logic becomes a team artifact.</p>
<p>The risk ladder Anthropic describes shows how teams are expected to use it. Low-risk changes, such as documentation or internal features behind feature flags, need no human approval. Medium-risk changes need one person. High-risk changes need two. Sensitive areas, including CI workflow files, always get human oversight. Review loops are capped at three rounds, because an agent author and an agent reviewer can otherwise keep each other busy indefinitely. Anthropic recommends that most customers enable Claude Approvals first in observe-only mode to build confidence before configuring branch protection to require its green light. Teams can start with one repository, choose a review level and when reviews run, and set a monthly spend limit per repository.</p>
<h2>Anthropic's own numbers, with the caveat attached</h2>
<p>Anthropic offers its own team as the first data point. On the Claude Code team, merged pull requests more than doubled from June to September, while the share of pull requests later reverted fell by more than 40 percent. Those are the numbers Anthropic puts forward as evidence the approach works, and the company attaches the caveat itself: its own reporting cautions that Claude Ship's impact was not isolated, and that its review is one layer in a broader process. The doubling and the falling reversion rate happened while the team was changing other things too, so the numbers show that a team using Ship shipped faster with fewer reversions, not that Ship alone caused either figure. A Gartner analyst, Nitish Tyagi, put it more bluntly, calling Claude Ship "not a breakthrough innovation as much as an evolution of existing AI-assisted code review capabilities." The honest reading is that Ship compresses the waiting between writing code and merging it. It does not remove the judgment from the decision.</p>
<h2>The limits, stated up front</h2>
<p>Ship has practical limits that matter more than the launch headlines. It works only with GitHub for now. It is available on Claude Team and Enterprise plans, and usage is token-based, with admins setting monthly spend limits per repository. Even observe-only approval policies can incur costs if they invoke classifiers or Code Review, so the cautious mode is not the free mode. Organizations using Anthropic's zero data retention or HIPAA configurations cannot currently use Claude Ship, and neither can those with self-managed encryption keys. <a href="https://www.byteherald.com/2026/11/anthropics-efs-safety-checks-without.html">Our November 23 post explained Anthropic's Enterprise Frontier Safeguards, the zero data retention product those customers use instead, and the exclusion is a direct consequence of how Ship works: the agents need to read the code and the review history to do their job</a>. Eligible Enterprise customers can claim at least $10,000 in promotional credits through January 15, 2027. And Anthropic includes the disclaimer that matters most: "Claude Ship uses AI and may miss bugs, security vulnerabilities, or other issues." Conventional static analysis and manual assessment remain necessary for critical code.</p>
<h2>What to do first</h2>
<p>For a team considering Ship, the rollout Anthropic recommends is also the sensible one. Pilot Code Review on one repository and watch what it flags before letting it near approvals. Run PR Steward manually at first, so a human sees each fix before it lands. Put Claude Approvals in observe-only mode and read its decisions for a few weeks before branch protection requires its sign-off. Write the policy file narrowly at first, approving only the lowest-risk changes, and widen it only when the observe-only record earns the trust. The product's value is that it moves the review bottleneck downstream of code generation. Its risk is that a team treats an approval policy as a formality and discovers, after a bad merge, that the policy was the only reviewer. The policy file decides what merges. Write it like it does.</p>
