<p>Claude went down twice on November 13, 2026. An authentication failure locked users out of claude.ai, Claude Code and the developer console from 09:58 to 11:58 UTC, and a second bout of degraded performance began at 13:09 UTC and was still being monitored that afternoon. A third problem, the Microsoft 365 connector, has been failing since the evening of November 12. This is the full timeline, taken from <a href="https://status.claude.com/">Anthropic's own status page</a>.</p>

<h2>The morning failure: sign-in broke at 09:58 UTC</h2>
<p>Anthropic posted its <a href="https://status.claude.com/incidents/nn11wk485zfn">first update</a> at 09:58 UTC, which was 3:58 a.m. Central, under the title "Elevated errors on claude.ai, Claude Code, and platform.claude.com." The company said it was investigating an issue with users authenticating to Claude.ai and Claude Code. In plain terms, people could not sign in, and existing logins stopped working. The services listed as affected were claude.ai, the Claude Console at platform.claude.com, Claude Code, and Claude Cowork. The Claude API at api.anthropic.com was not on that list, so apps built on Claude kept running while the chatbot itself was unreachable for many users.</p>
<p>At 11:05 UTC, about 67 minutes later, Anthropic said a fix had been deployed and it was monitoring for recovery. At 11:58 UTC, exactly two hours after the first update, it marked the incident resolved, saying the issue affecting claude.ai and Claude Cowork had been resolved. Downdetector, which counts user problem reports, recorded more than 3,800 Claude reports at about 10:15 a.m. UK time, falling to about 270 by 10:30 a.m., according to <a href="https://en.moneyandbanking.co.th/2026/287073/">The Sun</a>. Anthropic has not said what caused the authentication failure, and it has not given a time for a fuller explanation.</p>
<h2>The afternoon failure: degraded performance at 13:09 UTC</h2>
<p>The second incident began at 13:09 UTC, which was 7:09 a.m. Central, a little over an hour after the first one was marked resolved. Anthropic titled it the same way, "Elevated errors on claude.ai, the Claude API, and Claude Code," and said it was investigating reports of degraded performance. This time the API was on the affected list, along with the web app and the coding tool.</p>
<p>The scope widened through the morning. At 13:52 UTC the update added connectors, including Claude Docs and Claude Sheets. At 14:03 UTC it added Claude Security and Claude Managed Agents. At 14:36 UTC Anthropic reported it was seeing recovery on claude.ai and the Claude API, but warned errors may return while work continued, and said connectors including Docs and Sheets remained degraded, as did Claude in Meetings, Claude Managed Agents, Claude Security, and connector use in Claude Code. Mobile apps were affected in the same way as claude.ai. As of that update the incident was still open, with Anthropic promising another update soon.</p>

<h2>The Microsoft 365 connector is a separate, longer failure</h2>
<p>There is a third incident on the same status page, and it started a day earlier. Since 17:52 UTC on November 12, Anthropic has reported elevated errors and slow responses on the Microsoft 365 connector, the link that lets Claude read mail, calendars, SharePoint and Teams chats. On the evening of November 12 it said the issue was caused by a Microsoft 365 service incident, and that mail, calendar and search tools in the connector were still failing for most requests. Claude for Outlook remains affected. Anthropic pointed users to Microsoft's own status page for progress, and said its upstream provider was restarting affected servers.</p>
<p>That connector failure is the one place where Anthropic has named Microsoft as the cause, and it lines up with the Microsoft 365 outage that knocked out Outlook, Teams and Copilot across 74 countries. The two Claude incidents on November 13 are different: Anthropic has not linked either of them to Microsoft, and nothing on its status page supports that link. The morning failure was an authentication problem inside Claude's own sign-in path. Our report on the Microsoft 365 outage, published today, has the full scope of that failure, including the governments, airlines and hospitals it hit.</p>
<h2>How often this happens</h2>
<p>Three incidents in six days sounds alarming, but the status page history puts the scale in context. On November 8, Claude Fable 5.1 returned elevated errors for about 14 minutes. On November 10, Fable 5.2 and Mythos 5.2 were overloaded for four minutes. November 9 and November 11 had no incidents at all. The two short ones were blips on single models. November 13 is different because it hit the front door, sign-in, across the web app, the coding tool and the console, twice, and because the second incident reached the API as well.</p>
<p><a href="https://www.statuspal.io/status/claude">StatusPal</a>, a tracker that reads Anthropic's status page every minute, counts 15 Claude incidents in the last 30 days, adding up to about 37 hours of disruption. That count includes short model overloads like the November 10 four-minute event, so it overstates the time users actually lost, but it is a fair measure of how often something, somewhere in Claude, breaks. The honest reading is that Claude's core models rarely go down for long, while its sign-in and connector layers have now failed twice in one day.</p>
<h2>How to tell whether Claude is down</h2>
<p>The first check is <a href="https://status.claude.com/">Anthropic's own status page at status.claude.com</a>, which posts within minutes and lists each service separately. The per-service list matters, because the web app, the API, Claude Code and the console do not always fail together: on the morning of November 13 the API stayed up while the web app was down, and in the afternoon the API joined the affected list. Downdetector is the second check, useful for confirming that other people see the same thing, but its counts are user reports, not measurements, and they spike when a story spreads. A third signal is the model itself: <a href="https://www.byteherald.com/2026/11/claude-fable-52-built-os-in-8-days-it.html">Claude Fable 5.2, launched November 9, 2026</a>, is the model that overloaded for four minutes on November 10, so a Fable-only error points to a model problem rather than a platform one.</p>
<h2>What to do while it is down</h2>
<p>Do not keep re-entering your password or re-authenticating in a loop. An authentication failure on the provider's side will not be fixed by trying again, and repeated attempts can trigger rate limits that outlast the outage. If you use Claude Code, check whether the API is listed as operational, since the coding tool and the API have failed on different schedules today. If you rely on the Microsoft 365 connector, assume mail, calendar and search tools inside Claude will fail until Microsoft's own incident is resolved, and do that work in Outlook or Teams directly. The degraded connectors include Claude Docs and Claude Sheets, so anything you built with <a href="https://www.byteherald.com/2026/11/anthropics-office-suite-sent-microsoft.html">Anthropic's office suite, launched November 10, 2026</a>, is worth checking before you trust its output today. And keep a second provider available for time-sensitive work, because the lesson of November 13 is that the fallback can fail on the same day as the primary.</p>
