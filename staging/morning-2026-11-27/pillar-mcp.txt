<p><a href="http://workspaceupdates.googleblog.com/2026/11/mcp-servers-cli-standardized-usage-tiers-now-available.html">Google made its Workspace MCP servers generally available on November 24, 2026</a>, covering Gmail, Drive, Docs, Sheets, Slides, Calendar, Chat, and Tasks. ByteHerald counted the tools on Google's own MCP reference pages on November 27, 2026: the eight servers expose 87 tools on the approval-capable endpoint and 76 on the fallback endpoint. The 11 tools that exist only where a human can be asked first are the real permission map, and Gmail sending sits inside that gated set.</p>

<h2>The permission map, counted</h2>
<p>Each Workspace product has its own MCP server, and each server offers two endpoints. The primary endpoint, /mcp/v1, is built for AI clients that support form elicitation, the MCP mechanism a server uses to collect input from a person before finishing a tool call. The fallback endpoint, /mcp/v1self, serves clients that cannot show that approval form. <a href="https://developers.google.com/workspace/guides/configure-mcp-servers">Google's setup guide</a> says /mcp/v1 exposes all tools, while /mcp/v1self exposes only tools and results that work without form elicitation under default policy. The table below is ByteHerald's count of <a href="https://developers.google.com/workspace/gmail/api/reference/mcp">Google's MCP reference pages</a> for all eight servers, captured on November 27, 2026.</p>

<p>The pattern is narrow and consistent. The gated tools are the ones that send something to another person, delete something, reach into shared data, or apply a sensitivity label. Gmail keeps trash and spam-marking tools on the fallback endpoint, so the gate is not about destruction in general. It is about actions whose effects leave the user's own mailbox or touch other people's data. Google's guide names the protected class directly: sending emails, modifying shared calendar events, sharing or trashing files, and accessing shared data. Docs, Sheets, and Slides expose identical tool sets on both endpoints, because editing a document the user already owns does not cross that line by default.</p>
<h2>Can the Gmail server send email</h2>
<p>Yes, with a condition that explains the confusion in early coverage. Google's Gmail MCP reference lists send_message, reply, and forward among the 30 tools on /mcp/v1, and its quota page prices all three as generally available tools. None of the three appears on /mcp/v1self. An AI client that cannot present an approval form therefore gets a Gmail server that can search, read, draft, label, and trash, but cannot send. A client that supports form elicitation gets the send tools, and Google's server can still stop and ask before a sensitive send completes. The November 24 release-notes summary describes Gmail search, drafts, labels, trash, and spam handling without mentioning send, which is why the first wave of write-ups said the server could not send at all. The reference pages are the more complete record, and they say otherwise.</p>
<p>Approval behavior also depends on the target. Google's guide warns that specific calls on the fallback endpoint might still require approval depending on policy and target resources, and Workspace administrators can set review policies for external agents. Whether a given call prompts therefore depends on the organization's policy settings and the resource the call touches, not on the tool alone. Readers who want the failure-mode view of agent approvals will find it in <a href="https://www.byteherald.com/2026/10/ai-agents-in-production-what-breaks-and.html">ByteHerald's audit of what breaks when agents run in production</a>, which catalogs how approval gaps turn into incidents.</p>
<h2>The quota math</h2>
<p><a href="https://developers.google.com/workspace/gmail/api/guides/quotas">Standard Tier MCP usage is capped at 5,000 requests per day, per project, per product</a>, resetting at midnight Pacific Time. The cap counts requests, not tool calls, and the two differ. Gmail's search_threads and list_drafts each count as 10 requests, so a search-only Gmail agent can run at most 500 searches a day under the Standard cap. That figure is ByteHerald arithmetic from Google's published weights: 5,000 divided by 10. Failed tool calls still consume the daily limit and the per-minute rate limits, even when the failure is a permission denial or a declined user confirmation. An agent that retries a denied send in a loop burns quota without sending anything.</p>
<p>The pricing changes on a fixed date. Scaled Tier billing for MCP begins on April 1, 2027, and Gmail MCP has no daily no-charge allowance on that tier, so charges apply from the first successful request. Teams running agents at volume should model the quota before the billing date arrives, the same discipline <a href="https://www.byteherald.com/2026/10/the-agentic-cost-bomb-what-ai-agents.html">ByteHerald's ledger of what AI agents really spend at scale</a> applies to token budgets. The request cap is the MCP equivalent of a token budget, with the same failure mode: silent consumption by retries and background polling.</p>
<h2>The February 2027 mandate</h2>
<p>The permission map matters beyond Google's own servers because of a deadline. Google states that AI agents must reach Workspace data through the MCP servers or the Workspace CLI rather than calling Workspace REST APIs directly, with technical enforcement beginning on February 1, 2027. After that date, the approval endpoints, the quota weights, and the administrator controls in this map become the governed path for agent access to Gmail, Drive, and the rest of Workspace. Administrators get OAuth app access settings, user review policies for external agents, agent attribution, data loss prevention, and audit logging over that path.</p>
<p>Two practical checks follow for anyone connecting an agent now. First, confirm the client supports form elicitation and point it at /mcp/v1; a fallback connection silently loses the 11 gated tools, including every send. Second, budget the quota by request weight, not by tool call, and treat declined approvals as spent budget. Google's documentation has shifted during the launch window, so counts in this map are dated November 27, 2026 and should be rechecked against the reference pages before any production decision.</p>
