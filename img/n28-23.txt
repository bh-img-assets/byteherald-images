<p>ByteHerald recomputed Nolan Lawson's 12-framework agent benchmark as cost per million tokens, and the ranking flips. Angular, the most expensive build at $4.97, is among the cheapest per token at about $0.51 per million, while Hono+htmx, the cheapest build at $2.67, costs about $0.63 per million. The bill is not a price problem. It is a volume problem: the expensive frameworks made the agent spend up to 2.5 times as many tokens to build the same app.</p>

<h2>Volume, not price</h2>
<p>The recomputation separates two effects the headline ranking merges. Per-token cost varies only from about $0.50 to $0.73, a spread of roughly 1.5 times, and it does not track the total-cost ranking. Token volume varies from 3.85 million to 9.76 million, a spread of 2.5 times, and it tracks the bill almost exactly. Angular also took 17.2 minutes against Astro's 8.2 and produced 2,009 lines of code against 1,370 for Hono+htmx, so the expensive builds cost more to run, more to wait for, and more to maintain.</p>
<p>Lawson's own observations point to mechanism: agents repeatedly read outdated migration guides for some frameworks and often ignored the official tooling installed for them. Analysis: that pattern is consistent with training-data familiarity driving token volume, because an agent that knows a framework writes less exploratory code. The benchmark cannot prove that mechanism, but the per-token recomputation rules out the simpler story that some frameworks are priced higher per unit of work.</p>
<h2>Limits of the scorecard</h2>
<p>This is one content-heavy app, closer to a reference site than to a dashboard or game, built by one model in one agent harness. Adjacent cost ranges overlap, so the middle of the ranking is noise; only the ends, cheap lightweight stacks against expensive Angular, Gracile+Lit and SvelteKit, are defensible. Lighthouse-style metrics in the original benchmark favor server-rendered multi-page apps. The benchmark code is public on GitHub, so another team can rerun the spec and test where the ranking holds. Until then, the defensible claim is narrow: on this app, framework choice changed the agent's token volume by 2.5 times, and volume set the bill.</p>
<p>The practical reading for a team choosing a stack is about where to spend effort. If per-token prices are broadly similar, savings come from reducing the tokens an agent needs: current documentation in the repo, working official tooling the agent actually invokes, and examples in the codebase that match the framework's current version. Lawson installed official MCP servers or skills where they existed, yet agents often ignored them, which suggests the lever is not installing tooling but making the agent's first steps land on correct, current patterns. That is a testable claim, and the public benchmark gives any team the harness to test it on its own app rather than trusting a ranking built on one Pokemon site. The scorecard's value is that it turns a framework argument into a measurement any team can repeat before committing its own budget.</p>
