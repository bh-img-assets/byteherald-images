<p>ByteHerald's memory ledger gives the 2028 phone target a hard floor: a resident 100 billion parameter model does not fit in a 24 GB memory budget at any precision Qualcomm lists for its current flagship platform, even before key-value cache, runtime buffers, the operating system, or apps take space. At INT2, the weights alone need 25 GB by simple multiplication, which is already above the 24 GB ceiling. At INT4, the weights need 50 GB. The finding is narrow and useful because it separates a marketing target from a memory budget.</p>
<h2>The ByteHerald memory ledger</h2>
<p>Method: ByteHerald multiplied 100 billion parameters by bytes per parameter for FP16, FP8, INT4, and INT2, then compared the result with the up to 24 GB memory density in Qualcomm's Snapdragon 8 Elite Extreme Gen 6 product brief dated September 22, 2026. The same brief lists support for INT2, INT4, INT8, INT16, FP8, and FP16 precisions, including mixed precision. This is a weights-only ledger. It excludes key-value cache because cache size depends on layer count, key-value head count, head dimension, context length, and cache precision, none of which is fixed by the 100 billion parameter target.</p>

<h2>Analysis</h2>
<p>Analysis: the ledger does not say a 100 billion parameter phone is impossible. It says a dense, resident 100 billion parameter model cannot be described honestly as fitting in 24 GB unless the system changes what resident means. A mixture-of-experts model can carry a large total parameter count while activating only part of the network for each token, and a system can stream some weights from storage. Those designs change the memory question, but they also change the claim. The user-facing question becomes which parameters are resident, which are streamed, what latency the streaming adds, and whether quality holds at the chosen precision.</p>
<p>The target itself is a demand signal, not a product specification. On Qualcomm's fourth quarter fiscal 2026 earnings call on November 4, 2026, Cristiano Amon said leading AI companies are targeting smartphones by 2028 capable of running 100 billion parameter models locally with all-day battery life, and that reaching the goal will require a step-function change in on-device compute performance. That statement supports the direction of travel. It does not name a phone, a memory configuration, a model architecture, a benchmark, or a battery test.</p>
<p>The precision rows also need a quality warning. INT2 makes the arithmetic closest to the ceiling, but the ledger does not prove that a 100 billion parameter model quantized to INT2 would preserve reasoning quality, tool use, or long-context behavior. Qualcomm's product brief establishes precision support in silicon. It does not establish model quality at that precision. A citable phone claim would need the model card, quantization method, evaluation scores, context length, memory trace, and battery test to be published together.</p>
<h2>What the evidence does not establish</h2>
<p>The evidence does not establish that 2028 phones will ship with more than 24 GB of memory, that a sparse model should be counted the same way as a dense resident model, or that all-day battery life can coexist with continuous inference at this scale. It also does not establish the size of the key-value cache for any real 100 billion parameter phone model. Those omissions matter because the weights-only row is the floor, not the full memory bill.</p>
<p>What to watch next is specific: phone memory densities above 24 GB, published on-device memory traces for large models, quantization evaluations at INT4 and INT2, and battery tests that state tokens generated, context length, screen state, and thermal limits. Until those records exist, the honest summary is that the 100 billion parameter phone is a target with a memory gap, not a demonstrated device class.</p>
