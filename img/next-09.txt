<p>ByteHerald finding: in Anthropic's own memory tests, persistent memory helped mid tier Claude models far more than frontier models, and the headline wiki gain shrinks once search is counted. Recomputing every quantitative result in Anthropic's November 6, 2026 post shows the largest gain on the Continual Learning Bench database task belonged to Claude Opus 4.7, not to the newest models, while a dreaming built wiki beat search alone by 8 percentage points, not by the 35 points suggested by the wiki only headline. Checked memory helps most where the base model is weakest at learning from feedback, and a maintained wiki adds a modest gain over search on multi document questions.</p>
<h2>How ByteHerald built this ledger</h2>
<p>ByteHerald extracted each reported number and recomputed absolute change, relative change, and efficiency ratios. No table or wording was copied. Relative change means the with memory score minus the without memory score, divided by the without memory score. Files per badge means memory files at about 10,000 Pokemon Red steps divided by badges held then, counting the top level global file as one file for Claude Fable 5. Anthropic defines agent memory as experience knowledge retained between sessions as readable context, excluding weight changes and compaction. Dreaming is the offline pass that checks notes against transcripts and builds linked representations such as wikis.</p>

<p>Analysis: the ledger shows convergence at the top. The three strongest with memory scores sit within 0.010 of each other, from 0.828 to 0.838, while their baselines spread across 0.091, from 0.564 to 0.655. Memory looks less like a frontier multiplier and more like a floor raiser for models that can close a learning loop. Claude Sonnet 4.6 clarifies the condition: it gained only 0.034 until Anthropic prompted it to read memory and test theories, after which Anthropic reports its score nearly doubled. Anthropic also reports Claude Sonnet 5 read memory before answering 9 times in 10 without prompting, against less than half the time for Claude Sonnet 4.6. Salience points the same way. Claude Fable 5 held 4 badges with about 165 times fewer files per badge than Claude Sonnet 3.7, because it stored strategy and tested rules rather than screen readable state. Anthropic gives no file count for Claude Opus 5.5, so ByteHerald computes no ratio for it.</p>
<h2>What dreaming corrected, and where the wiki did not help</h2>
<p>The clearest dreaming result is a correction, not a score. Claude recorded the Mt. Moon PokeCenter on the wrong side of the mountain, trusted that note, crossed a one way ledge three times in the uncorrected run, and never reached Cerulean City. After dreaming checked the note against the transcript and rewrote it, Claude reentered Mt. Moon and reached Cerulean City. Anthropic reports the same pattern in wiki repair: one pass repointed 9 links to a missing page and added 3 pages including an index. Wiki evidence is mixed by task. On merger questions needing several documents plus judgment or math, the wiki led search by 14 points. Where brief criteria could be retrieved by text search from a single document, Anthropic reports no clear gain. On another task the wiki grew larger than the documents, which Anthropic presents as abstraction failure. The contract task shows why structure matters: parallel writes to a shared table overwrote facts and produced 41 of 57 facts, while single author pages quoting terms verbatim reached 100 percent. Claude Code applies the same restraint at the top layer, loading only the first 200 lines or 25 KB of its memory index into each session.</p>
<h2>Limits: what this evidence does not establish</h2>
<p>These results do not establish that dreaming improves production agents in general. The Pokemon comparison rests on one run each. The Stainless corpus holds about 350,000 internal files and about 420 million tokens that outside readers cannot inspect, and the wiki score rests on 25 questions with no run counts or error ranges in the post. The CL-Bench figures come from one database task through Claude Managed Agents, with each question in a fresh session and only a memory directory carrying over. Anthropic states that dreaming costs compute and that the right cadence remains open. The sleep time compute paper reports about 5 times less test time compute at equal accuracy, but its tasks were author built and favor predictable queries. Builders should copy the discipline shown, then measure on their own tasks.</p>
