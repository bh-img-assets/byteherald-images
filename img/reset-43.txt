The notes credit the change as suggested by and with extensive feedback from Chris Rohlf in collaboration with Claude and Anthropic Research. The same release enabled the hybrid post-quantum ssh-mldsa44-ed25519 signature algorithm. That pairing matters: the algorithm gained an explicit role while the check moved earlier, which is a different outcome from removing the algorithm.</p><h2>What the evidence does not establish</h2><p>Analysis: the ledger supports a method claim, not a safety claim. Anthropic's counts show that reachability mapping found default-exposed code and configuration interactions at scale in the projects examined. The OpenSSH notes show one upstream project accepted an earlier-check fix and credited the collaboration. Neither document establishes that the 493 issues were exploitable vulnerabilities, that attacks fell afterward, or that the same density exists in codebases outside the 25 examined. The report itself frames the findings as attack-surface issues, and the gated-project findings were described as not immediately exploitable on their own.</p><p>The citable residue is narrow and durable: a dated upstream release changed where a security check sits, and a dated lab report published the counts behind the method. Future claims about AI code auditing should be graded against that residue, not against the headline number alone.</p><p>The method transfers without a frontier model, which is why the ledger is worth keeping. A team can map which parsers and protocol handlers a default deployment exposes before authentication, list the configuration options that change that exposure, and test pairs of security-sensitive settings for silent interactions. Each step produces a dated artifact: a reachability map, an option inventory, and a combination test record. Those artifacts are what make a later claim checkable, and they are the difference between an audit story and an audit record.</p><p>That record discipline also protects the original claim from drift. When a later release changes a check, a dated ledger shows which version carried which behavior, instead of letting a summary sentence float free of the release that made it true.</p><p>By ByteHerald Staff.
