<p>ByteHerald's finding: the five best-known agent memory systems differ less in what they remember than in how a wrong memory ends. Only Zep and Graphiti keep a validity window on every fact by default, recording when a fact stopped being true instead of overwriting it. Mem0 accumulates facts and retires them by expiry date or scoped delete. Letta corrects by file edit and keeps the old version in git history. LangMem leaves the correction path to the developer. A team choosing on benchmark scores alone will miss the property that decides whether a bad memory can be removed.</p><h2>The correction-path ledger</h2><p>ByteHerald compiled the ledger below from vendor documentation as synthesized in dated comparisons read in full for this report. Zep's temporal graph stores validity intervals on fact edges, so a superseded fact is invalidated rather than erased, and a user's threads, artifacts, and graph can be deleted in a single call. Cognee builds its graph from the team's own documents, code, and database rows, with a forget operation and a temporal mode that keeps superseded facts. Mem0's pipeline is add-only: memories accumulate, and a fact that stops being true is retired by an expiry date set at write time or by an explicit delete scoped to a user, agent, app, or run. Teams must check their installed version, because older Mem0 documentation describes an extraction pass that updates and deletes facts.</p><p>Curatorship splits it further. Letta's agent edits its own memory files in a git-backed filesystem, which makes correction an audit trail and a retention decision at the same time: the wrong fact leaves the current files but stays in history. LangMem provides primitives inside LangGraph, so consolidation and correction are whatever the developer builds, including background jobs that update entries. Analysis: deletion guarantees are therefore a product property in Zep, a configuration property in Mem0 and Cognee, a history property in Letta, and an application property in LangMem.</p><p>The benchmark caution belongs in the same ledger. In one cited comparison at about 26,000 tokens per conversation, sending the whole history beat every tool inside Mem0's own table, while longer histories reversed the result. Vendor scores use different readers and judges. The correction path, by contrast, can be read directly from documentation and tested in an afternoon.</p><h2>Methodology and limits</h2><p>Methodology: ByteHerald extracted storage model, curator, correction path, and deletion aftermath for each system from the dated syntheses, each of which states that its mechanism claims come from vendor documentation, and cross-checked the validity-window claim against a September 28, 2026 recheck.
