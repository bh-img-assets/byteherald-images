<h2>Why cost per task is the deciding measure</h2>
<p>Computer-use agents do not buy tokens in isolation. They buy completed tasks that may need screenshots, retries, tool calls and long context. A cheaper model that needs more attempts can cost more per finished job. OpenAI's launch claims therefore need independent task tests with success rate, elapsed time, token use and failure mode reported together. Vendor benchmark scores alone do not establish the cheapest reliable route.</p>
<p>Analysis: Terra's strongest case is high-volume work where the task is bounded and verification is cheap. Examples include form filling with a known schema, screen extraction, routine document edits and first-pass coding changes reviewed by tests. The weaker case is open-ended work where a failed attempt consumes human review time. In that setting, a higher-priced model can be cheaper if it finishes with fewer corrections.</p>
<h2>What buyers should verify</h2>
<p>Teams should measure cost per accepted task on their own workload, including cached-token share and prompts over 272,000 input tokens, where surcharges apply. They should also separate ChatGPT Work and Codex subscription access from API billing, because the launch record names paid plans for product access and per-token billing for API use. Security review matters as well because the model is built to act across applications.</p>
<p>Analysis: the citable point is arithmetic, not a benchmark crown. Terra halves input price against its predecessor and cuts output by more than half. Whether that becomes a lower bill depends on token mix, cache behavior, retries and review cost. Those are measurable in a pilot and should decide routing.</p>
